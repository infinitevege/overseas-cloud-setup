# 阿里云国际新账号第一周：从首次登录到第一台 ECS 上线

很多团队拿到阿里云国际（alibabacloud.com）账号后，第一件事就是开机器部署业务，几周后才发现主账号没开 MFA、安全组对全网开放了 22 端口、余额快用完了也没人知道。这篇把第一周拆成七个检查点，按顺序做完再上正式业务。

> 适用对象：刚完成 [阿里云国际开户](https://www.clouddalao.com/cloud/aliyun-intl) 或刚接手一个新主账号的团队。控制台菜单名称以官方最新界面为准。

## 第 1 天：登录核对

| 检查项 | 在哪里看 | 通过标准 |
| :--- | :--- | :--- |
| 账号 UID | 控制台右上角头像 → 账号信息 | 与交付信息一致，记入团队台账 |
| 账号身份 | 账号信息页 | 是主账号，不是 RAM 用户登录 |
| 站点 | 浏览器地址 | `alibabacloud.com`，不是 `aliyun.com` |
| 初始余额 | 费用与成本 → 账户总览 | 与订单的到账金额一致 |

UID 是后续 [充值](https://www.clouddalao.com/recharge) 时唯一要填的账号标识，建议当天就写进密码管理工具的备注里。

## 第 2 天：主账号加固

1. 把初始密码改成只有负责人知道的强密码。
2. 绑定虚拟 MFA（任意 TOTP 身份验证器 App 均可），把恢复方式记录在团队的安全文档里。
3. 把联系邮箱和手机换成团队长期使用、离职不会失效的地址。
4. 检查是否存在 AccessKey：主账号原则上不保留 AccessKey，程序调用改用 RAM 用户。

RAM 用户怎么建、权限怎么拆，可以参考 [阿里云国际 RAM 访问控制入门](https://www.clouddalao.com/guides/alibaba-cloud-ram-users-permissions)。

## 第 3 天：先定地域，再建网络

地域一旦选定，ECS、云盘、VPC 都绑在那里，跨地域迁移要重新建资源。决定前用真实用户位置测一下延迟，方法见 [国际云地域怎么选](https://www.clouddalao.com/guides/pick-cloud-region-latency-test)。

建网络时只记住三件事：

- 为每个环境（生产 / 测试）单独建 VPC，网段不要重叠，方便以后打通。
- 交换机（vSwitch）按可用区建，至少规划两个可用区。
- 安全组默认拒绝入站，只放行业务端口；SSH / RDP 只对办公出口 IP 放行。

## 第 4 天：第一台 ECS

先开一台最小规格的按量付费实例做连通性测试，确认镜像、网络、带宽计费方式都符合预期，再决定正式规格和付费方式。测试实例用完当天释放，避免持续计费。

上线前对照这张表：

- [ ] 公网带宽计费方式（按固定带宽 / 按使用流量）已确认
- [ ] 系统盘、数据盘类型与容量已确认
- [ ] 登录方式使用密钥对，禁用密码登录
- [ ] 实例和云盘都打了 `env`、`project`、`owner` 三个标签

## 第 5 天：监控与告警

在云监控里为 CPU、内存、磁盘、公网流量设阈值告警，通知对象至少两个人。只有一个人接收告警，等于没有告警。

## 第 6 天：费用提醒

在费用与成本中心设置余额预警，阈值建议覆盖至少 7 天的正常消耗。余额预警只负责提醒，不会自动补款；补款请走 [充值](https://www.clouddalao.com/recharge)，账号上的实例和 IP 不会变化。更完整的预算设置思路见 [国际云余额告警与预算设置](https://www.clouddalao.com/guides/cloud-budget-alerts-avoid-suspension)。

## 第 7 天：复盘

把这一周的结果整理成一页：UID、负责人、MFA 持有人、VPC 网段、告警接收人、余额预警阈值。这一页就是以后交接账号时的底稿。
