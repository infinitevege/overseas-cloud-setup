# 团队用 USDT 付云费用：一张对账台账该记哪些字段

个人付款，记得住就行；团队付款，三个月后就没人说得清某一笔 USDT 是给哪个账号充的。这篇给出一张可以直接复制的台账模板和填写规则。

> 三条链（TRC20 / ERC20 / BEP20）的区别和转账前核对，见 [USDT 付款指南](https://www.clouddalao.com/guides/usdt-trc20-erc20-bep20-payment)。

## 台账模板

| 字段 | 示例 | 谁来填 | 说明 |
| :--- | :--- | :--- | :--- |
| 日期 | 2026-11-04 | 付款人 | 以链上确认时间为准 |
| 类型 | 开户 / 充值 | 申请人 | 二选一 |
| 云平台 | 阿里云国际 | 申请人 | |
| 账号标识 | UID 或 AWS 登录账号 | 申请人 | 开户时先留空，交付后补 |
| 项目 | shop-prod | 申请人 | 和云上标签保持一致 |
| 订单号 | — | 付款人 | 订单页显示 |
| 到账金额（USD） | — | 付款人 | 订单核对页显示 |
| 应付 USDT | — | 付款人 | 订单核对页显示 |
| 网络 | TRC20 | 付款人 | 与订单一致 |
| 实际转出 USDT | — | 付款人 | 含交易所提币手续费 |
| 交易哈希（TxID） | — | 付款人 | 完整复制，不要截断 |
| 订单状态 | 已支付 | 付款人 | 以订单页为准 |
| 云端核对 | 已核对 | 技术负责人 | 在云平台费用中心确认余额变化 |

## 填写规则

1. **一笔订单一行**，不要把多笔合并。
2. **「应付 USDT」和「实际转出 USDT」分开记。** 两者的差额就是手续费，月底汇总手续费时直接求和。
3. **交易哈希必须完整。** 它是链上唯一凭据，付款未确认时排查全靠它，排查步骤见 [USDT 付款未到账怎么办](https://www.clouddalao.com/guides/usdt-payment-not-confirmed-troubleshooting)。
4. **云端核对由另一个人做。** 付款人和核对人分开，可以避免大部分低级错误。

## 月底十分钟对账

1. 按「项目」汇总到账金额，与各云平台账单的当月消费对比。
2. 按「网络」汇总实际转出 USDT，与钱包或交易所的出金记录对比。
3. 找出「订单状态」不是已支付、或「云端核对」为空的行，逐一处理。

## 开户与充值分开看

- **开户**：订单交付后，把新账号的 UID 或登录账号补进台账，以后所有充值都用这个标识。开户入口见 [开户页](https://www.clouddalao.com/open-account)。
- **充值**：只受理经本站开通的账号，按账号专属折扣计价，入口见 [充值页](https://www.clouddalao.com/recharge)。

开户档位与计价方式会随后台配置调整，以 [费率说明](https://www.clouddalao.com/rates) 和下单核对页为准。
